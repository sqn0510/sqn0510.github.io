前言

往年的漏洞报告中，注入类漏洞始终位列前三，而其中出现频率最高、危害面最广的就是 SQL 注入（SQL Injection）。本文将从原理出发，手把手带你理解并复现 SQL 注入攻击，最后给出实用的防御方案。

什么是 SQL 注入

SQL 注入是一种通过将恶意 SQL 语句插入到应用程序输入参数中，从而操控后端数据库的攻击方式。其本质是 用户输入的数据被当作 SQL 代码执行。

SQL 注入的常见类型

1. Union 联合查询注入

最直观的一种注入方式，利用 UNION SELECT 将攻击者想要的数据追加到正常查询结果中。

前提：页面会直接显示查询结果。

Union 注入三步走：

  1. 用 ORDER BY 判断列数
  2. 用 UNION SELECT 1,2,3... 确定回显位置
  3. 在回显位置替换为攻击 payload

2. 报错注入

当页面不直接显示数据，但会输出数据库错误信息时使用。

常用报错函数：extractvalue、updatexml、floor() + rand()。

3. 布尔盲注

页面完全无回显也无报错，但不同的输入会导致页面返回 不同状态（正常/异常）。

注入过程：逐字符猜测 → 根据页面返回状态判断正确与否 → 不断二分缩小范围。

4. 时间盲注

最隐蔽也最耗时的一种——无论输入什么，页面返回都一样，唯一区别是 响应时间。

常见的注入位置

除了 URL 参数，这些地方也可能存在注入点：

位置 示例
GET/POST 参数 ?id=1，登录表单
Cookie Cookie: user_id=123
HTTP 头 User-Agent、Referer、X-Forwarded-For
JSON/XML 输入 {"username":"admin"}

2. 输入验证与过滤

  • 白名单校验：对数字类型强制转换，对枚举值限定范围
  • 转义特殊字符：' " \ ; -- # 等

3. 最小权限原则

应用的数据库账户只授予必要权限，禁止使用 root 或 sa 账户连接数据库。

4. 部署 WAF

使用 ModSecurity、Cloudflare WAF 等拦截常见的注入 payload。

总结

层面 措施
代码层 参数化查询、ORM 框架
输入层 白名单校验、类型强制转换
数据库层 最小权限、禁用危险函数
网络层 WAF 拦截
运维层 关闭报错、定期渗透测试

SQL 注入虽然古老，但在 CVE 年度报告中始终占有一席之地。理解其原理并做好防御，是每一位安全从业者的必修课。
